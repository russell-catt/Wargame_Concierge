# KB/units/

One page per **datasheet**, written in **play terms** - how the unit is used, not a copy of its profile.

**Type:** `unit` · **Filenames:** lowercase `snake_case` · **Schema:** [`AGENTS.md`](../../AGENTS.md) Sec 4, Sec 6

## Suggested sections

| Section | Content |
|---------|---------|
| Role | What job this unit does in a list |
| Durability | How hard it is to remove, and to what kind of damage |
| Threat range | Where it can reach, and by which turn |
| How to use it | Deployment, movement pattern, what it should be shooting or holding |
| How it dies | The common mistakes that waste it |
| Pairings | Units and characters it works with, with links |
| Owned | Whether the models are on the shelf, and their build state |

## Do not transcribe the datasheet

No statlines, no verbatim weapon profiles, no copied ability text. Describe the unit's behaviour in your own words and cite where the reader can check the numbers against material they own ([`AGENTS.md`](../../AGENTS.md) Sec 10). If a page cannot be written without copying the datasheet, it is not ready to be written.

## Cross-linking

Every unit page links back to its Faction and to any Detachment that particularly wants it.

## Naming

Prefix with the faction when a name is shared across armies: `necron_warriors.md`, `canoptek_scarab_swarms.md`, `immortals.md`.
